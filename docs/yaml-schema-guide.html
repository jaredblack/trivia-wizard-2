Trivia Wizard — YAML Schema Guide

Everything the trivia event YAML supports, what each field controls on the slides, and copy-paste examples.

Generated from frontend/src/features/host/trivia-schema.json (authoritative schema), the presentation renderer frontend/src/presentation/build.ts, and type defaults in frontend/src/types.ts. Local reference — not deployed.

required slide-deck (visual) server config (gameplay)

# Overview

A trivia event is a single YAML document with a title, optional subtitle, and an ordered list of slides. Each slide has a type that selects how it renders and what fields it accepts.

title: Friday Night Trivia
subtitle: Week 12
slides:
  - type: category      # section divider
    title: Round 1 — Music
  - type: question      # a trivia question
    id: mus
    question: Who released "Thriller"?
    answer: Michael Jackson

The four slide types are category, question, image, and custom. A title slide is auto-generated from the top-level title/subtitle and shown first — you don't add it yourself.

# The one thing to understand: two layers

Fields on a question fall into two independent layers. Keeping them straight explains almost every field in this guide.

Slide-deck layer (visual) What the audience sees on the projector. question, answer, choices, matching, images, notes, and the category/image/custom slides. Never sent to the server.
Server config layer (gameplay) How Trivia Wizard scores the question: questionKind, timerDuration, questionPoints, bonusIncrement, speedBonusEnabled, and the config block. Sent at question-creation time.
Server fields are seed values, not locks Anything in the server-config layer is applied when the question is created, then host UI edits during the game always take precedence and are never reverted. Any omitted field falls back to the current global default at creation time. So YAML config sets the starting point; the host can override live.

# Top-level document

FieldTypeRequiredControls
titlestringyesBig heading on the auto-generated title slide (first slide of the deck).
subtitlestringnoSmaller line under the title on the title slide.
slidesarrayyesOrdered list of slides. Rendered top-to-bottom after the title slide.

The document is strict: unknown top-level keys are rejected (additionalProperties: false). The same is true of every slide type — a typo'd field name is a validation error, not a silent no-op.

# type: category — section divider visual

A full-screen divider with a large centered title. Use it to announce rounds/categories. Purely visual; it is not a question and gets no number.

FieldTypeRequiredControls
type"category"yesSelects this slide type.
titlestringyesLarge centered category name.
subtitlestringnoSmaller line below the title.
imagesarray of imageRefnoDecorative images shown in a row below the title. All shown immediately (no reveal logic on category slides).
notesstringnoSpeaker notes — visible only in the host/presenter view, never to the audience.
- type: category
  title: Round 2 — Geography
  subtitle: Grab a map, it gets hard
  images:
    - globe            # shared image cdn/images/globe.*
    - ./compass        # this event's images/compass.*
  notes: Remind teams the tiebreaker is in this round.

# type: question — a trivia question

The workhorse slide. Top-level fields drive the on-screen layout; the config block plus a few peer fields configure scoring on the server. The renderer auto-picks a layout based on which fields are present.

Slide-deck fields visual

FieldTypeRequiredControls
type"question"yesSelects this slide type.
idstring, 3 lettersyesStable ID matching ^[A-Za-z]{3}$. Drives the displayed question number — see numbering.
questionstringyesRendered as Q: … at the top of the slide.
answerstringnoRendered as A: … but hidden until you advance — appears as a reveal fragment. Slide-deck only; never sent to the server.
choicesarray of stringnoMultiple-choice options rendered as an A/B/C… list. Also implies questionKind: multipleChoice when kind is omitted (see note below).
matching{left[], right[]}noTwo-column matching exercise: numbered left column, lettered right column. Slide-deck only.
imagesarray of imageRefnoQuestion images with reveal timing & position. See Images.
notesstringnoHost-only speaker notes.

Server-config peer fields gameplay

FieldTypeControls
questionKindstandard · multiAnswer · multipleChoice · numeric · mapHow teams answer & how it's scored. Omitted → current global default, except presence of choices implies multipleChoice.
timerDurationinteger ≥ 1Per-question countdown in seconds. Omitted → global default.
questionPointsinteger ≥ 0Points for a correct answer. Omitted → global default.
bonusIncrementinteger ≥ 0Step size for the host's manual bonus +/− buttons. Omitted → global default.
speedBonusEnabledbooleanWhether the speed bonus applies to this question. Omitted → global default.
configobjectKind-specific scoring config — see the config block.
choices is the one dual-purpose field choices does two jobs: it draws the A/B/C list on the slide and, when questionKind is omitted, it tells the server this is a multipleChoice question with numOptions = number of choices. Set questionKind explicitly if you want to show options on screen but score it as some other kind.

Minimal question

- type: question
  id: cap
  question: What is the capital of Australia?
  answer: Canberra

Multiple choice (kind inferred from choices)

- type: question
  id: flm
  question: Which film won Best Picture in 1994?
  choices:
    - Pulp Fiction
    - Forrest Gump
    - The Shawshank Redemption
    - The Lion King
  answer: B — Forrest Gump   # server gets multipleChoice, numOptions: 4

Matching exercise

- type: question
  id: cty
  question: Match the country to its capital.
  matching:
    left:  [Japan, Egypt, Peru]     # numbered 1,2,3
    right: [Cairo, Lima, Tokyo]     # lettered A,B,C
  answer: 1-C, 2-A, 3-B

Question with kind + scoring config

- type: question
  id: pop
  question: What's the population of Iceland (2024)?
  answer: ~393,000
  questionKind: numeric
  timerDuration: 45
  questionPoints: 10
  speedBonusEnabled: false
  config:
    scoringMode: closestGuess

# type: image — title + one centered image visual

A slide with optional title text and a single centered image. The canonical use is the join-the-game QR code.

FieldTypeRequiredControls
type"image"yesSelects this slide type.
titlestringnoHeading above the image. Use YAML | for multi-line text.
imagestring (an image ref)noThe centered image. Same resolution rules as elsewhere, but string form only — no reveal/position object here.
notesstringnoHost-only speaker notes.
- type: image
  title: |
    One person from each team:
    Join the game on Trivia Wizard
    Game code: ABCD
  image: trivia-wizard-join-qr

# type: custom — raw HTML escape hatch visual

When the built-in slide types aren't enough, drop in your own HTML — either inline or from a file. The content is injected directly into a slide <section>.

FieldTypeRequiredControls
type"custom"yesSelects this slide type.
htmlstringno*Inline HTML rendered as-is inside the slide.
filestring (path)no*Path to an HTML file, fetched and injected. ./slides/foo.html → this event's folder; a bare path → the shared CDN; /path → passthrough.
notesstringnoHost-only speaker notes.

*Provide one of html or file. For file: http(s):// URLs are rejected, and .. path segments are rejected (they'd escape the bucket boundary).

- type: custom
  html: '<h1>Intermission</h1><p>Back in 10 minutes</p>'
- type: custom
  file: ./slides/halftime.html

# Images: references, reveal timing & position

How an image reference resolves

Anywhere an image is accepted, the string is resolved like this (matched by filename stem, minus extension, case-insensitive):

You writeResolves to
kfrShared CDN image: cdn/images/kfr.<ext>.
./kfrThis event's folder: <event>/images/kfr.<ext>.
/path/to/x.pngAbsolute path — passthrough, unchanged.
https://…Remote URL — passthrough, unchanged.
Resolution is strict If a bare/./ name matches zero files in the manifest, or more than one (e.g. both kfr.png and kfr.jpg), the build throws an error. Keep stems unique.
Background convention The deck background is resolved from a shared image named bg (cdn/images/bg.<ext>). You don't reference it in YAML — just make sure a bg image exists.

Object form: reveal and position (question slides)

On question slides, each image can be a string or an object with two knobs:

FieldValuesControls
urlimage ref requiredThe image, using the resolution rules above.
revealquestion · answerquestion = visible immediately. answer = appears with the answer reveal fragment.
positionside · centerside = right column beside the text (default). center = hero image filling the available space.
⚠ Schema vs. renderer: the reveal default differs The JSON schema's description says reveal defaults to answer, but the actual presentation renderer (build.ts) treats a missing reveal as question — i.e. an image with no reveal shows immediately, not on the answer. To avoid ambiguity, set reveal explicitly whenever timing matters. (position defaults to side in both places — consistent.)

The "swap" behavior

Within a position group (side or center), if you provide both a question-reveal image and an answer-reveal image, the renderer cross-fades them: the question image fades out and the answer image fades in when you advance. If you provide only an answer image, it simply appears alongside the answer.

# Show a mystery photo, then swap to the labeled photo on reveal
- type: question
  id: act
  question: Name this actor.
  answer: Keanu Reeves
  images:
    - url: mystery-actor
      reveal: question
      position: center
    - url: actor-labeled
      reveal: answer
      position: center

# Question numbering & the id field

Displayed question numbers are not taken from id directly. Instead:

  • Numbers are assigned by order of first appearance of each unique id (case-insensitive). The first distinct id seen is "Question 1", the next new id is "Question 2", and so on.
  • Two slides that share the same id share the same number — handy for a follow-up/context slide that belongs to the same question.
  • When several slides share an id but carry settings, the first occurrence's config and server overrides win.
- type: question
  id: art        # → Question 1
  question: Who painted this?
  images: [{ url: painting, reveal: question, position: center }]
- type: question
  id: art        # → still Question 1 (same id), e.g. the answer reveal slide
  question: Who painted this?
  answer: Johannes Vermeer — Girl with a Pearl Earring
- type: question
  id: geo        # → Question 2
  question: …

# The config block gameplay

Server-side scoring configuration sent to Trivia Wizard when the question is created. Fields are interpreted according to questionKind; settings that don't match the kind are ignored. Every field is optional and falls back to the current global default.

FieldApplies toTypeControls
numAnswersmultiAnswerint ≥ 1Number of answer slots teams fill in.
optionTypemultipleChoiceletters · numbers · yesNo · trueFalse · otherLabel format teams pick from.
numOptionsmultipleChoiceint ≥ 2Number of options. Defaults to choices.length if choices is set, else the global default.
scoringModenumericexactOnly · range · closestGuessHow submitted numbers are scored.
fullPointsDistanceKmmapnumber ≥ 0Within this distance of the target, full points.
onePointDistanceKmmapnumber ≥ 0Distance at which a guess scores exactly 1 point; beyond it, rounds to zero.
Numeric: only scoringMode is settable from YAML For numeric questions, the remaining knobs (rangeType, rangeValue, numWinners, rangeScoringType) are not in the YAML schema — they stay host-adjusted at game time. YAML only seeds scoringMode.

# Question kinds at a glance

KindHow teams answerRelevant config
standardFree-text answer.—
multipleChoicePick one labeled option. Inferred when choices is present.optionType, numOptions
multiAnswerFill several answer slots (e.g. "name 3 …").numAnswers
numericSubmit a number; scored by distance/exactness.scoringMode
mapDrop a pin on a map; scored by distance to target.fullPointsDistanceKm, onePointDistanceKm

multiAnswer

- type: question
  id: grt
  question: Name 3 of the Great Lakes.
  answer: Any 3 of: Superior, Michigan, Huron, Erie, Ontario
  questionKind: multiAnswer
  questionPoints: 9
  config:
    numAnswers: 3      # 9 pts / 3 slots = 3 pts each

multipleChoice with True/False labels

- type: question
  id: tfq
  question: A tomato is botanically a fruit.
  answer: True
  questionKind: multipleChoice
  config:
    optionType: trueFalse

map

- type: question
  id: pin
  question: Drop a pin on Machu Picchu.
  questionKind: map
  config:
    fullPointsDistanceKm: 25
    onePointDistanceKm: 2000

These are the config defaults baked into the app (frontend/src/types.ts). They apply when a field is omitted and the host hasn't changed the corresponding global default in Settings.

Timer duration, question points, bonus increment, and speed-bonus enablement default to whatever the host has set as the global default in the Settings panel; there's no fixed YAML default for those.

# Full example deck

A complete, valid event exercising most features:

title: Friday Night Trivia
subtitle: Week 12 — the hard one
slides:
  # Join slide
  - type: image
    title: |
      One person per team:
      Join on Trivia Wizard — code ABCD
    image: trivia-wizard-join-qr

  # Round 1
  - type: category
    title: Round 1 — Movies
    subtitle: Lights, camera, guessing

  - type: question
    id: flm
    question: Which film won Best Picture in 1994?
    choices: [Pulp Fiction, Forrest Gump, Shawshank, The Lion King]
    answer: B — Forrest Gump
    notes: Common wrong answer is Shawshank.

  - type: question
    id: act
    question: Name this actor.
    answer: Keanu Reeves
    images:
      - { url: mystery-actor, reveal: question, position: center }
      - { url: actor-named,   reveal: answer,   position: center }

  # Round 2
  - type: category
    title: Round 2 — Geography

  - type: question
    id: pin
    question: Drop a pin on Reykjavík.
    questionKind: map
    timerDuration: 60
    config:
      fullPointsDistanceKm: 25
      onePointDistanceKm: 3000

  - type: question
    id: pop
    question: Population of Iceland (2024)?
    answer: ~393,000
    questionKind: numeric
    config: { scoringMode: closestGuess }

  # Wrap-up
  - type: custom
    html: '<h1>Thanks for playing!</h1>'

# Gotchas & tips

  • Strict objects. Every level rejects unknown keys — a misspelled field name fails validation rather than being ignored.
  • 3-letter IDs only. id must match ^[A-Za-z]{3}$. They don't need to be meaningful, just unique per distinct question.
  • reveal default is ambiguous. The renderer treats missing reveal as question (shown immediately); the schema text says answer. Set it explicitly. (See Images.)
  • Image stems must be unique. kfr.png + kfr.jpg both matching kfr is a build error.
  • answer, matching, and choices labels are deck-only. They never reach the server — the server scores teams' submitted answers against what the host marks correct in the UI.
  • Server config is a starting point. Live host edits during a game always win and are never reverted by the YAML.
  • Repeat an id to give a question a context/answer-reveal companion slide that shares its number. First occurrence's config wins.
